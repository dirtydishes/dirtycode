The decision

Keep the verified durable runtime. Replace its low-level product entrance with a conversation-fed creator and a plain-language Program runner inside T3 Code.

The proposal is editable draft truth. Dirtyloops validates it. T3 starts the accepted revision and makes every related conversation reachable without flooding normal recents.

Product contract

The workspace is an operator view, not a runtime dump. Facts and allowed actions lead; raw identities, receipts, leases, paths, and adapter details stay in Diagnostics.

Outcome and state
What we are building, factual progress, and only the controls the server allows.
Needs you

Now
Every active Phase, current role, current work, last meaningful update, and thread link.
Next
Ready work and plain blocking reasons, derived from the accepted dependency graph.
Done
Settled work, collapsed by default but retained as evidence.

Thread placement

Program-bound threads live under their Program. Opening one does not promote it into normal recents. Attention and the current thread may surface beneath the Program row; explicit pinning is the only path into the normal pinned area.

One fact, one owner

Each system keeps the decisions it can prove. Models may propose and explain, but they never decide readiness, state, attention, Admission, integration, or completion.

Source freeze

This build changes Dirtycode only. The installed Dirtyloops skill and its matching source in the Agents repository remain frozen inputs for all five Phases. Any verified Dirtyloops defect needs a separate issue, plan amendment, and user approval.

Build and review policy

Implementation moves one public behavior at a time. Formal review waits for a complete Phase candidate, then all required roles inspect the same revision and evidence.

Test-driven implementation

  1. Name the public seam and expected behavior in the Phase turn doc.
  2. Get user agreement on that seam before writing its first test.
  3. Write one behavior-focused test and prove the intended failure.
  4. Add only enough implementation to make that test pass.
  5. Repeat one vertical red-green slice at a time at the accepted seam.
  6. Refactor only after green, during review, without changing accepted behavior.

  1. One candidate

    Every required role receives the same completed Phase revision, tests, gates, CI, and acceptance proof.

  2. All callbacks

    Wait for every role. Thermonuclear stays separate; adversarial and product reviewers cannot consult its skill.

  3. One repair owner

    Combine and deduplicate all blocking findings into one batch, owned by one mutable checkout.

  4. Full rerun

    Run affected red-green tests, every Phase gate, and every required role again against the repaired candidate.

Three-pass stop

Repair pass 0 is the initial review. Repair passes 1 and 2 are the only authorized repair batches. A third rejected review pass stops before another repair and asks the user for fresh authority. There is no repair pass 3 by default.

Five tracer Phases

The graph is serial on purpose. Each Phase delivers a real end-to-end user outcome and gives the next Phase a stable public seam to deepen.

01

Create and finish one real Program

Plain intent becomes one accepted single-Phase Program, one real provider result, one Admission, and one integration.

02

Make work understandable and reachable

Needs you, Now, Next, Done, search, breadcrumbs, pinning, evidence, and a complete task directory remove sidebar clutter without hiding work.

03

Make controls and recovery reliable

Pause, resume, stop, retry, and replan converge once across lost responses, process restart, reconnect, and stale revisions.

04

Run bounded multi-Phase Programs

Dependencies, safe parallel selection, separate worktree permits, budgets, repair history, and optional map views scale the model without splitting authority.

05

Finish mobile, remote, and accessibility support

Web, desktop, and mobile operate one remote Program with matching facts, controls, attention, placement, and bounded queries.
